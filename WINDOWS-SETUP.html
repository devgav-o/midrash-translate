Live translation — Windows setup & class routine

Everything needed to get this running on the classroom laptop, and what to do at the start and end of each class.

On this page One-time setup Every class Restarting Troubleshooting Projector keys

Part 1 — One-time setup Do this once on the classroom laptop. Allow about 45 minutes, and you need internet for this part only.

  1. Install Python 3.12

    Go to python.org and download Windows installer (64-bit) for Python 3.12.

    Two things that will break setup if you get them wrong

    1. In the installer, tick “Add python.exe to PATH” at the bottom of the first screen before clicking Install.

    2. Use 3.12, not 3.13 or 3.14, and install from python.org — not the Microsoft Store version. The translation library has no Windows build for the newer versions yet.

  2. Install Git

    Download from git-scm.com and click through the installer accepting every default.

  3. Download the code

    Open the Start menu, type PowerShell, press Enter. Then paste this in and press Enter:

    cd C:\
git clone https://github.com/devgav-o/midrash-translate.git
cd midrash-translate

    You now have the project at C:\midrash-translate.

    Why C:\ and not the Desktop or Documents

    If those folders sync to OneDrive, OneDrive will keep grabbing the files while the program is reading them several times a second. Keep it on a plain local path.

  4. Run the installer script

    In the same PowerShell window:

    powershell -ExecutionPolicy Bypass -File scripts\setup_windows.ps1

    This takes 20–40 minutes and downloads about 4 GB. It sets up Python's libraries and then downloads the three translation models so they work with no internet later. Leave it alone until it prints “Setup complete.”

  5. Check it is fast enough 
    .\.venv\Scripts\python.exe scripts\benchmark.py
.\.venv\Scripts\python.exe scripts\check_markers.py

    The first prints translation speed per language — anything under about 500 ms is comfortable. The second confirms the glossary is being applied.

  6. Test it without Word

    This proves the screens and the network work, before adding Word to the picture.

    .\.venv\Scripts\python.exe run.py --backend echo --file demo_transcript.txt
    A Windows Firewall box will pop up

    Tick Private networks and click Allow access. Without this the projector machines cannot reach the page. It only asks once.

    The window prints a few web addresses. Open them in a browser — you should see the demo lines. Then open demo_transcript.txt in Notepad, type a line, save it, and watch it appear on the pages.

    Press Ctrl+C in the PowerShell window to stop it.

  7. Test it with real Word

    Open Word, type two or three lines, and leave Word open. Then in PowerShell:

    .\.venv\Scripts\python.exe run.py -v

    Look for a line saying connected to source. Type in Word — the translations should appear about a second later, with no saving.

    This is the step most likely to fail

    The Word connection was written on a Mac and has never met a real copy of Word. If it does not connect, copy the whole PowerShell output and send it over — do not do this test for the first time on the morning of a class.

  8. Optional — better Hebrew

    Hebrew is the weakest of the three offline models. If the classroom has internet, get a free key at aistudio.google.com/apikey and run this once per PowerShell window, before run.py:

    $env:GEMINI_API_KEY = "paste-your-key-here"

    Nothing breaks without it — Hebrew just falls back to the offline model automatically, including if the internet drops in the middle of a class.

Setup is done

From here on, everything is Part 2. You never repeat Part 1 unless the laptop is wiped.

Part 2 — Every class About two minutes of setup, and one minute at the end.

Before class

1. Open Word and start a brand-new blank document.

Start a new document, do not reopen last week's

When the program starts it reads whatever is already in the document and translates all of it. Reopening an old transcript means the whole thing gets re-translated onto the projectors before the lesson has begun.

2. Start the program. Open PowerShell and paste:

cd C:\midrash-translate
.\.venv\Scripts\python.exe run.py

It prints a set of addresses that look like this:

  control panel   http://192.168.1.42:8000/
  Francais        http://192.168.1.42:8000/display/fr
  Espanol         http://192.168.1.42:8000/display/es
  Hebrew          http://192.168.1.42:8000/display/he

3. Open each projector's page. On each projector machine, open a browser, type in that language's address, and press F for fullscreen.

4. Leave the PowerShell window open. Minimise it if you like — closing it stops the translation.

Order does not matter

Word before the program, or program before Word — either way. It keeps retrying until it finds the document.

During class

Nothing to do. The transcriber types in Word as usual; editing and deleting lines is fine and the projectors follow along.

If you want to keep an eye on it, the control panel address shows how far behind each language is, how many projectors are connected, and any errors.

After class — export first, then close

Export before you close anything

The translations live only in the program's memory. Closing the PowerShell window first loses them permanently — the English is still safe in Word, but the French, Spanish and Hebrew are gone.

Open the control panel address — in any browser, on the classroom laptop or on your phone — and take your pick under Download the transcript:

ButtonWhat you get
All languages (.zip) One download with all four Word files inside — French, Spanish, Hebrew, English. The usual choice.
All as one PDF Opens a printable page and the print dialog. Pick Save as PDF as the destination. One PDF, one language per page.
.docx / PDF per language Just one language, when that is all somebody wants.
Save .docx to sessions folder Writes the four files onto the classroom laptop at C:\midrash-translate\sessions\, in a folder named for today's date. Nothing downloads — use this when you want the archive to stay on that machine.
Why PDF goes through the print dialog

The browser already lays Hebrew out correctly, right-to-left, with no internet. Printing from it gives a better PDF than the program could build itself, and there is nothing extra to install.

Then go to the PowerShell window, press Ctrl+C to stop it, and save the Word document as usual.

Do I restart it between classes? Yes. Short answer: stop it after every class, start it fresh for the next one.

SituationWhat to do
New class Restart. Press Ctrl+C, start a new Word document, run run.py again. If you leave it running, the new class's lines pile on top of the last one's and the export mixes both classes into one file.
Back-to-back sessions, same transcript Leave it running. Nothing gained by restarting.
A projector page froze or was closed Just reload that page. It refills with the whole lesson so far. No need to touch the program.
Word was closed by accident Reopen it. The program reconnects on its own. Anything typed while Word was shut arrives on reconnect.
The laptop went to sleep Check the control panel. If a language looks stuck, restart the program — but export first if the lesson has content worth keeping.
Translations stopped or fell far behind Download the transcript, Ctrl+C, run run.py again. It picks the document back up from the top.

If something goes wrong

What you seeFix
python is not recognised Python was installed without “Add to PATH”. Re-run the Python installer, choose Modify, and tick it.
Projector page will not load The firewall box was missed or denied. Windows Security → Firewall → Allow an app → find Python → tick Private. Also confirm both machines are on the same Wi-Fi.
Page loads but stays empty Check the PowerShell window for connected to source. If it is missing, Word is not open, or it is watching a different document.
First line takes ages, rest are fine Normal. The models load on the first translation. Type one throwaway line before class starts.
Everything lags behind Open config.yaml in Notepad and lower debounce_ms from 700 to about 400. Restart the program.
Lines flicker and rewrite while typing The opposite fix — raise debounce_ms to 1200. Restart the program.
Text too small at the back Press + on that projector, or raise display.font_size_px in config.yaml to make it permanent.
Hebrew reads badly Expected from the offline model. Set the Gemini key (step 8) if there is internet in the room.
A term keeps coming out wrong Add it to glossary.json and restart. This is the cheapest way to improve quality.
Something else Restart with run.py -v, reproduce it, and send the PowerShell output.

Getting later fixes onto this laptop

When the code is updated, in PowerShell:

cd C:\midrash-translate
git pull

If the update also changes the required libraries, run this after it:

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
